01

Fictional helpdesk boundary

Four genuine in-process MCP tools read and mutate local classroom JSON. send_reply records a local fixture entry; there is no real email transport or external helpdesk API. A production adapter would need separate authentication, idempotency, delivery tracking and authenticated reviewers.

02

Permission ordering

Bare allowedTools entries may bypass canUseTool. The sender is excluded; default permission mode falls through to the callback. The tool handler also consumes an exact one-use ticket/body grant so an unintended permission bypass cannot record an unapproved reply.

03

Edited input

The decision route accepts body edits but no ticketId. canUseTool returns the original ticket ID and reviewed body in updatedInput. The handler verifies that exact pair and refuses a second reply for a ticket in the same run.

04

Rejection and expiry

Reject uses native deny. The prompt forbids retries or alternate delivery routes. Pending requests expire after two minutes or abort with the run, and stale/replayed decisions return 409. Retry policies and stronger durable idempotency would be needed for a production service.

05

Errors are explicit

Missing ticket is a genuine MCP isError response for fictional T-404. Historyerror deliberately fails the local history fixture, not a real provider. The agent should explain the gap rather than invent previous contacts.

06

Automatic local tagging

set_priority mutates only the run JSON and is explicitly automatically allowed for this exercise. It is not annotated read-only. Production tagging policies may need additional review.

07

Limits and typed output

Normal queries allow twelve turns and a $0.35 SDK estimate threshold; estimates can overshoot before being checked. Turnlimit allows one turn and preserves the native error. Structured uses the actual SDK JSON schema output followed by Zod validation.

08

Batch and audit

Batch makes one fresh SDK query per ticket, sequentially, while sharing this run local JSON. Each sender call requests an independent decision. PostToolUse captures actual responses; approval decisions retain the original and approved body.

09

Credentials and privacy

Keep the API key only in the private .env or shell. SDK state is disposable; runtime JSON and audits stay local and are excluded from Git. This is a fictional classroom fixture, not comprehensive production DLP or a secure multi-user deployment.
